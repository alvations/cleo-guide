## How to read this

- **ID** — `M<milestone>-<nn>`. IDs are permanent; a dropped item is struck through, never renumbered.
- **Lane** — `DES` designer · `PLT` platform/tech lead · `FE-A` city page · `FE-B` hubs/nav/search · `QA`.
  The first lane listed owns the item; others contribute.
- **Effort** — S (≤1 session) · M (2–3 sessions) · L (4+ sessions).
- **Acceptance** — every criterion is testable. Unless stated, "mobile" = 390×844 @DPR3 touch, "desktop" =
  1440×900, measured by the beta metrics harness (M0-04) on the **pilot set**: `beta/cleveland.html`,
  `beta/cities/tokyo.html`, `beta/cities/newyork.html` (largest US), `beta/Singapore/chinatown.html`, `beta/cities/wheeling.html`
  (smallest US) and the beta hub. Rollout items (M1-22) re-run the same checks on **every** beta page.
- **Global acceptance (applies to every item, never restated):**
  1. `cd tools && npm run validate && npm test` pass; `check-google.py` passes on `beta/`.
  2. QA harness: **0 FAIL** on beta at mobile and desktop.
  3. Every beta page carries **exactly** the P/F records of its live counterpart (generator count assert).
  4. Page content renders with every off-origin request blocked; no `document.write`; every storage call in
     try/catch with an in-memory fallback.
  5. Nothing fabricated: every number, date, name and image on screen is derived from data or is an original,
     generic glyph. No ratings, review counts, "popular"/"trending", prices or hours.
  6. "Recommended by" attribution visible on every card; closed places stay, flagged; stated gaps stay stated.

## Acceptance protocol (how the PM accepts or rejects)

An item is **Accepted** only when all three are attached to its BETA-LOG entry:
1. **QA evidence** — harness run (`qa/summary.json` excerpt) + beta metrics JSON for the pilot set.
2. **Design review** — mobile + desktop screenshots signed off by DES against the benchmark rows the item cites.
3. **PM check** — each acceptance criterion ticked with the measured value. A criterion with no measurement is
   a reject, not a pass.

Status values: `todo` · `doing` · `review` · `accepted` · `rejected (reason)` · `deferred (reason)`.
