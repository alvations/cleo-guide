# Countries — the top-level navigation (US · Singapore · Vietnam · …)

The guide is multi-country. The **root `index.html` is the country hub**: it opens on the **United States**
city list (the default view) and offers a switcher to each other live country's own hub. This is **data,
not code** — it lives in [`data/countries.json`](../data/countries.json) and is consumed by
`tools/build-singapore-pages.py` (for the engine-built countries) and by the hand-authored `index.html`
(for the US cards + the country switcher).

This is the reuse mechanism. To bring the **next** country live you add/enable one entry in
`data/countries.json` and run the build — you do **not** restructure anything.

## The rule: every country gets its own hub page, then the cities inside it

**A country is never a bare link to a single city.** Each live country has its **own hub page** (a
country landing page) that lists the cities/regions **inside** it; the root `index.html` switcher links to
that hub, never straight to a city. This is how Singapore (→ its towns) and Vietnam (→ its cities) already
work, and it is the required shape for **every** country added from here on. When a country would launch
with only one city, still give it a hub with that one city on it — the second city then just slots in.

## The three kinds of country

```jsonc
{ "key":"us",        "kind":"us",             "live":true,  "hub":"index.html" }
{ "key":"singapore", "kind":"engine",         "live":true,  "region":"Singapore", "folder":"Singapore", "hub":"Singapore/index.html" }
{ "key":"vietnam",   "kind":"engine",         "live":true,  "region":"Vietnam",   "folder":"Vietnam",   "hub":"Vietnam/index.html" }
{ "key":"germany",   "kind":"dataset-cities", "live":true,  "folder":"Germany",   "hub":"Germany/index.html", "pages":["cities/saarland.html","cities/aachen.html"] }
{ "key":"malaysia",  "kind":"engine",         "live":false, "region":"Malaysia",  "folder":"Singapore" }
```

- **`kind:"dataset-cities"`** — a country whose guides are the **dark-engine dataset cities** (the same
  `cities/<city>.html` builds as the US cities: `build-<city>.py` → gates), grouped under a **hand-authored
  hub** at `<folder>/index.html` in the dark theme (mirror `Germany/index.html`). `pages` lists the city
  guides the hub links to (relative to repo root); the guides stay in `cities/` — only the hub moves into
  the country `folder`. Each such city guide's footer back-link points at its country hub
  (`../<folder>/index.html`), set in its `build-<city>.py`. Germany is the first of these (Saarbrücken &
  the Greater Region + Aachen & the Dreiländereck). Use this kind for any non-US country whose guides are
  cross-border/regional dataset cities rather than the pastel one-page-per-place engine.

- **`kind:"us"`** — the US cities, built by the dataset/engine city builds (`cleveland.html` +
  `cities/*.html`) and listed **by hand** in `index.html`. There is one of these.
- **`kind:"engine"`** — the pastel one-page-per-place guides cloned from the Cleveland engine by
  `tools/build-singapore-pages.py` (Singapore towns, Vietnam cities, and the future SEA countries).
  - **`region`** MUST match the region string used in that build's `PLACES` table.
  - **`folder`** is where the country's place pages **and** its own hub (`<folder>/index.html`) are
    written. Today only **Vietnam** has its own folder; **Singapore** and the not-yet-live SEA countries
    share the `Singapore/` folder so the archived all-SEA index (`Singapore/singapore-old.html`) keeps
    resolving. Give a country its own folder when you want its URL to read right (as Vietnam's does).
  - **`live`** — surfaced in the nav. `false` countries are built into files but not shown; they are
    reachable only from `Singapore/singapore-old.html` until populated.

## What each layer emits

- **`index.html`** (root, hand-authored) — the country hub: US cards (default view, under `#us`) + a
  country switcher card per live engine country linking to its `hub`. Add a country's card here when it
  goes live. Also links the archived all-SEA index.
- **`<folder>/index.html`** (generated) — one pastel hub per live engine country, listing **only** that
  country's places (Singapore → its towns; Vietnam → its cities). Which individual pages are clickable is
  `LIVE_SLUGS` in the build; the rest are greyed "expanding soon".
- **`<folder>/<slug>.html`** (generated) — the per-place engine pages.
- **`Singapore/singapore-old.html`** — the **archived** combined all-SEA index (every SEA country, most
  greyed). Preserved so no work is thrown away; its Ho Chi Minh City link points at the new `../Vietnam/`
  home. It is a frozen snapshot — not regenerated by the build.

## "We populate US, Singapore and Vietnam first"

Only those three are `live:true`. The rest stay `live:false` and out of the main nav until each is built
out **through the full pipeline** — sources → fact-check → re-rank → location-verify (see
[PIPELINE.md](PIPELINE.md), [SOURCES.md](SOURCES.md)). No place goes on a map from memory; every pin is
sourced and coordinate-verified into `data/geocodes.json` first. Bringing a country live is never an
ad-hoc page — it is the same discovery/verify flow every city gets, then flipping `live:true`.

## Bring the next country live (checklist)

1. **Populate it** through the pipeline: its places discovered, ≥2-credible-sourced (or lone
   institutional), fact-checked open/closed, geocoded + location-verified into `data/geocodes.json`. Its
   places carry the country's `region` in `tools/build-singapore-pages.py` `PLACES`.
2. In `data/countries.json`: set the country `live:true`; give it its own `folder` if you want a clean
   URL (else it shares `Singapore/`). If it's a metro city, also add its `data/metros.json` entry
   (districts + outskirts + corridors — see [METROS.md](METROS.md)).
3. Add the country's `LIVE_SLUGS` entries in `tools/build-singapore-pages.py` for the pages that are ready.
4. Add its switcher card to the root `index.html` (mirror the Singapore/Vietnam cards).
5. `python3 tools/rebuild-city.py singapore --build` → `node tools/test-singapore.js` (tests every live
   folder's pages + hub) → `python3 tools/check-google.py` + `check-escapes.py`. The test globs live
   folders from `data/countries.json`, so a new folder is covered automatically.
