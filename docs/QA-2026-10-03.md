# Site-wide QA — 2026-10-03

Automated browser QA of every published page on mobile and desktop, plus the fixes that came out of
it. Re-run any time with `cd tools && npm run qa` (the harness is `tools/qa-site.js`; raw results go
to `qa/results.json` and `qa/summary.json`, screenshots to `qa/screenshots/`).

## How it was tested

- **Pages:** all **160** HTML pages under the repo root, except `tools/*.html` (developer helpers).
  That is `index.html`, `cleveland.html`, `cities/` (33), `Singapore/` (49), `Vietnam/` (4), `Japan/`,
  `Germany/`, `Belgium/`, `beta/` (67, the restyled mirror) and `versions/v1-shortlist/` (2, linked
  from the hub).
- **Engine:** real Chromium through Playwright 1.56, served by an in-process static server so relative
  links behave as they do on GitHub Pages.
- **Viewports:** mobile is 390×844 (isMobile, hasTouch, DPR 3, iOS UA). Desktop is 1440×900.
- **Three loads per page, 480 loads in total:**
  1. **mobile, offline:** every off-origin request is aborted. This is what the sandbox egress does,
     and it is the scenario CLAUDE.md rule 4 covers.
  2. **desktop, offline:** the same, at desktop size.
  3. **desktop + map:** the Leaflet CDN URLs are served from `tools/node_modules/leaflet`, and tile
     requests get a 1×1 PNG. This checks that the map mounts, that markers draw, and that every
     base-layer chip switches to a no-key tile host.
- **What each load checks:**
  - JS errors: `pageerror` and `console.error`. Blocked-network noise is counted separately.
  - Local 404s.
  - "API key required" text.
  - Viewport meta.
  - That content renders.
  - Horizontal overflow, with the elements that cause it.
  - Text smaller than 12px (body copy) and smaller than 11px (labels).
  - Mobile tap targets smaller than 40px.
  - Every internal `href` and `#anchor`, read from the **rendered** DOM.
  - On the 145 engine pages: that a filter chip changes the list, that search reaches 0 results on
    nonsense and finds a real name, that the Sights↔Food switch works, and that the cuisine chips work.
  - Performance: bytes, DOM nodes, FCP, the largest inline script, image bytes, and the render-blocking
    `<head>` resources as authored.
- **Grading:** a page FAILs on anything functional. It gets a WARN for small type, small tap targets,
  or an empty Food mode.

D1–D3 below. Other results:

- **JS errors:** none from our own code. All 1,698 console errors were blocked-CDN or font noise,
  which is expected offline.

  zero markers).

- **Mobile overflow:** no page overflows horizontally on mobile.

Before the fixes, the first run had **22 FAIL loads**:

- Youngstown (live and beta) was broken.
- 16 of the FAILs were search false positives from a harness bug, which is fixed in the harness.

**Recommendations, in order:**

1. **D4.** Make the font and Leaflet CSS non-blocking. This is the only render-path cost, it applies
   to every page, and it is cheap to do.
2. **D5.** Batch-render lists on the 400+ place pages, but only if they keep growing.
3. **Beta pages** pay roughly 25 KB extra for the inline brand CSS and SVG. If beta replaces live,
   move that into a shared cached `.css` file.

FCP figures are measured on localhost with the CDN blocked, so they show the page's own render cost,
not network latency.

## Re-running

```bash
cd tools && npm install          # first time (jsdom, leaflet); Playwright + Chromium are preinstalled
npm run qa                       # full site, sample screenshots → qa/
node qa-site.js --only cities/   # subset → qa/partial/ (never clobbers the full run)
node qa-site.js --all-shots      # screenshot every page
```

The script exits 1 if any page FAILs, so you can use it as a pre-publish gate.
